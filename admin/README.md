# 운영 콘솔 (공개 웹)

**https://programmerson717.github.io/crypto-news-bot/**

Claude 계정이 없어도 누구나 열 수 있다. 봇이 폴링할 때마다 자동으로 갱신된다.

| 화면 | 주소 |
|---|---|
| 상태판 | `/` — 가동 여부·폴링 리듬·실행 이력·탭별 발행·최근 발행·백업 |
| 인수인계 | `/handoff.html` — 문서를 **역할별로** 갈라 놓은 것 |

## 왜 별도 DB(Mongo 등)를 안 쓰나

리포가 public 이라 히스토리를 여기 쌓으면 계정·비밀번호·네트워크 설정 없이
누구나(그리고 나중에 이 저장소를 여는 누구든) 그대로 읽는다.
DB 를 붙이면 자격증명이 하나 더 생기고, 그게 또 하나의 고장 지점이 된다.

| 파일 | 하는 일 |
|---|---|
| `docs/status.json` | 최신 스냅샷 |
| `docs/history.jsonl` | 시점별 기록. 한 줄 = 한 시점, 최근 3000줄 유지(약 40일) |
| `docs/handoff.json` | HANDOFF.md + RULES.md 를 역할별로 가른 것 |

## 갱신

봇이 폴링할 때마다 워크플로가 자동으로 돌린다. 손으로 하려면:

    venv/bin/python admin/snapshot.py --write
    venv/bin/python admin/build_docs.py

## 상태 판정 기준

마지막 발행이 얼마나 오래됐는지로 정한다.

- **정상 가동** — 45분 이내 + 루프 진행 중
- **느려짐** — 90분 이내
- **멈춤 의심** — 그 이상

실행 목록의 `취소(cancelled)` 는 실패가 아니다. 루프가 도는 동안 들어온 예약이
대기열에서 밀려난 것이다. 진짜 기준은 **발행 이력이 20분 간격으로 쌓이는지**다.

## 문제가 생겼을 때

상태판의 **상태 내려받기** 로 JSON 을 받아 그대로 주면 된다.
git 상태·실행 이력·폴링 간격·발행 분포·히스토리가 다 들어 있다.
